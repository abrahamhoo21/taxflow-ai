# Engineering Guidelines & Agent Rules (`AGENTS.md`)
> This document defines the engineering standards, architecture constraints, and quality gates for AI agents and developers working on the **YYC taxPOD CRM & Tax RAG Assistant** codebase.
> **All AI agents MUST read and adhere strictly to these rules before proposing or writing code.**

---

## 1. Core Architecture Principles: Clean & Layered Architecture

The project enforces strict **Separation of Concerns (SoC)** across 4 distinct layers. Code must never bleed across layer boundaries:

```
┌────────────────────────────────────────────────────────────┐
│ 1. Presentation Layer (`src/app/`, `src/components/`)       │
│    • Pure UI & Client Components.                          │
│    • NO direct database queries or raw external API keys.  │
│    • Only communicates with Backend via API Route Handlers.│
├────────────────────────────────────────────────────────────┤
│ 2. API & Controller Layer (`src/app/api/`)                 │
│    • Next.js Server Route Handlers.                        │
│    • Validates incoming HTTP payloads with Zod schemas.    │
│    • Delegates business logic to Service Layer.            │
├────────────────────────────────────────────────────────────┤
│ 3. Service & Business Domain Layer (`src/lib/`)            │
│    • Pure business logic, RAG retrieval orchestration,     │
│      prompt formatting, and hallucination guardrails.      │
│    • Framework-agnostic where possible.                    │
├────────────────────────────────────────────────────────────┤
│ 4. Infrastructure & Data Layer (`src/db/`, `supabase`)     │
│    • PostgreSQL DDL (`schema.sql`), pgvector RPC calls.    │
│    • Typed database client wrappers (`supabaseAdmin`).     │
└────────────────────────────────────────────────────────────┘
```

---

## 2. The "Zero Hardcoding" Rule (Maintainability First)

1. **No Magic Numbers or Strings**:
   - Any threshold, timeout, status name, or default value must be imported from centralized constants (`src/constants/crm.ts` or `src/constants/tax.ts`).
   - Example: **NEVER** write `if (opp.stage === 'Qualified')`. **ALWAYS** write `if (opp.stage === OPPORTUNITY_STAGES.QUALIFIED)`.
2. **Centralized Configuration**:
   - All external endpoints, API model names, and keys must be read through typed environment wrappers (`process.env.GEMINI_API_KEY`), never hardcoded in scripts.
3. **Malaysian Currency Standards**:
   - All financial amounts must be tracked in **Malaysian Ringgit (MYR / RM)**.
   - Use centralized currency formatting utilities (`formatRM(value)`).

---

## 3. TypeScript Strictness & Type Safety

1. **Zero `any` Policy**:
   - The use of `any` is strictly prohibited. Use `unknown` with type narrowing, generics, or defined interfaces.
2. **End-to-End Type Sharing**:
   - Database return types and frontend component props must share the single source of truth in `src/types/`.
3. **Runtime Schema Enforcement (Zod)**:
   - All AI structured outputs (e.g. Option B Meeting Notes Extractor) and external webhook payloads MUST be parsed and validated through Zod schemas before persistence.

---

## 4. RAG & AI Integration Guardrails

1. **Citation Completeness**:
   - Every factual answer generated by the Tax RAG system MUST contain explicit source citations: `[Doc: ..., Page: ..., Section: ...]`.
2. **Strict Hallucination Prevention**:
   - If vector search returns chunks below the cosine similarity threshold ($\ge 0.50$), the system MUST return the predefined grounded refusal message. Never let the LLM speculate on statutory tax law.
3. **Human-in-the-Loop (HITL) for Generative Actions**:
   - Any AI action that creates or modifies database records (such as parsing notes into CRM leads) must require explicit human confirmation via an editable review UI before saving.

---

## 5. UI/UX Standards

1. **Design System & Visual Consistency**:
   - Follow the **Modern Enterprise Dark SaaS aesthetic** (Tailwind slate palettes, subtle borders, high contrast).
   - Use Lucide icons consistently.
2. **Defensive UI States**:
   - Every data-fetching component MUST handle 3 states: **Loading** (skeleton/spinner), **Error** (user-friendly message), and **Empty** (clear call-to-action).

---

## 6. Pre-Commit / Pre-Delivery Checklist for Agents

Before concluding any implementation turn, the agent must verify:
- [ ] No hardcoded credentials or API keys exist in git-tracked files.
- [ ] TypeScript compilation passes with zero type errors (`npx tsc --noEmit`).
- [ ] All new files are placed in their respective clean folders per `ARCHITECTURE.md`.
- [ ] Documentation (`README.md`, `ARCHITECTURE.md`, `AI_USAGE.md`) is kept in sync with code changes.
